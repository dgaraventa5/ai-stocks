# Hermes engineering context

This repository is a public AI-infrastructure research and portfolio-model codebase. Use this file for engineering operations. `CLAUDE.md` remains the canonical domain-methodology record; read the relevant section before changing scoring, portfolio, research, or execution behavior. Do not rewrite or silently reinterpret that methodology.

## Scope and approvals

- Engineering work may maintain code, tests, CI, generated governance artifacts, and operational documentation.
- Do not provide discretionary stock or trade recommendations.
- Do not change scoring bands, category weights, portfolio selection/sizing, execution gates, or research methodology without explicit approval.
- Ask before destructive actions, migrations, schedule changes, deployments, or changes that can affect live data or orders.

## Git discipline

- Fetch first and branch from current `origin/main`; never develop directly on local `main`.
- Keep unrelated user work intact. Do not reset, clean, stash, or reformat unrelated files.
- Use repository-local identity `Dom Garaventa <20175478+dgaraventa5@users.noreply.github.com>`.
- Do not push, create/modify a PR, merge, or change repository settings unless the current task explicitly authorizes it.

## Environment and checks

- Supported Python is 3.10+; CI uses Python 3.12. The local migration environment uses `.venv`.
- Install declared runtime dependencies from `requirements.txt`; do not upgrade or add dependencies casually.
- Full suite: `.venv/bin/python -m pytest tests -q`.
- Run focused tests first, then the full suite. Run `git diff --check` and syntax/static validation for changed workflow, Python, JSON, and plist files.
- Site checks when site/export behavior changes: `python scripts/export_site_data.py` and `python scripts/check_site.py`.
- A failing repository gate is not waived. Preserve the reproduction and fix the source-of-truth artifact or code.

## Generated and governed data

- `00-master/ai_supply_chain_scoring.xlsx` is the live workbook. Preserve formulas and do not edit methodology as incidental cleanup.
- `00-master/cohort-membership.md` is generated from the workbook. Refresh only with `python scripts/cohort_membership.py --update`, review the complete diff, and verify that no methodology changed.
- Do not hand-edit generated governance projections when a canonical generator exists.

## Privacy boundary

- Everything under `tracking/live/` is gitignored and may contain real account values, share counts, order IDs, tickets, receipts, and reconciliation snapshots. Never stage, commit, publish, quote, or copy that content outside its approved local/backup boundary.
- Public artifacts such as `tracking/live-status.json` and `tracking/live-vs-model.json` must remain sanitized. Never weaken `tests/test_privacy_live_trading.py` or the site privacy tests.
- Do not expose credentials, tokens, account identifiers, or private email addresses.

## Live-order boundary

- `scripts/execute_ticket.py` is the only authorized order-writing code path.
- Never run `execute_ticket.py --confirm`, call a broker/order-write tool, transmit an order, clear a trading halt, or bypass an execution gate without explicit approval in the current task.
- Scheduled agents remain read-only toward brokerage systems. A test of execution code must use test doubles and must not contact a live broker.
- Do not load or resume the `com.dom.aistocks.executor` launchd service unless explicitly approved. Editing or testing its plist does not authorize loading it.

## Scheduling and automation

- Claude tasks, Hermes cron jobs, launchd jobs, and GitHub Actions can overlap. Before enabling or repointing a scheduled writer, inventory all existing owners and ensure exactly one writer per artifact.
- Creating, enabling, resuming, or changing a scheduled task requires explicit approval. Leave paused jobs paused unless the task says otherwise.
- GitHub Actions is the scheduled owner of `tracking/performance-series.json`; validate generated data before any commit/push.
- The local launchd plist preserves the separately controlled 06:35 open-mode executor path. It must not schedule the duplicate 13:35 performance-series writer.

## Branch and PR completion

- Review the complete diff for privacy, security, generated artifacts, methodology drift, and unintended workbook changes.
- Record exact test and static-check commands and results.
- Never claim CI is green without reading the remote checks, and never claim a PR is merged without reading its remote state.
